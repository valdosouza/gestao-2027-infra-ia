# Mudanca Estrutural
	Toda a tabela devera ter uma campo DELETED inciando com o Valor N
	Essa mudanca vai atingir todo o sistema pois tudo vai virar soft delete
	Isso vai permitir que tudo seja devidamente sincronizado insert e update
	Gerencia Registros deletados poderiam causar muitos problemas, pois o registro deletade deveria ser guardado para saber o que deletar, o que tornaria redundante
	
	
# Fluxo da sincronia	
	Tabela x é alterada (insert ou update)
	Registro na tabela sincronia com o nome da tabela, numero do registro, data e hora
	Syncronizador entra em acao
		consulta a tabela tb_Lista_Sincronia
		faz um loop para saber quais quais tabelas devem ser sincronizadas
			Para cada registro consulta a ultima data e hora de envio
				Faz a consulta na tb_sincronia dos registros que foram alterados depois do ultimo envio
					Envia registro a registro usando a factory
						O retorno deve atualizar o campo SRC_LOG(com ok ou erro encontrado) e a lista sincronia com a data e hora do ultimo registro	
							Isso garante que se durante o loop der algo de errado ele retoma de onde parou
							
# Operacoes automaticas
	o sistema devera excluir os dados da tabela sincronia obedecendo os seguintes criterios
		Campo SRC_LOG igual a ok
		A data e hora do campo SRC_TIME deve estar com a diferenca de tempo de 48 horas na hora da exclusao
