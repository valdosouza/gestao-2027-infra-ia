# Comparison folder, manifest and session file

**Scope**: method

Companion of [the backport skill](../SKILL.md), steps 0, 1 and 5. Every command here is
read-only for the repository and for every working copy; it writes only under the
comparison root, which lies outside all of them. Fictional values: the matching line
`branches/2.x` (svn) or `release/2.x` (git), the target `hotfix/2.1.7-1`, revisions r4120
and r4135, commits `a1b2c3d` and `e4f5a6b`.

## Layout

```
<comparison-root>/
  <backport-id>/                 one per backport (for example hotfix-2.1.7-1)
    session.md                   inputs, order, file registry, end validation, prepared commands
  <revision>/                    one per revision
    manifest.md
    log.txt
    diff/<path>.diff             the isolated diff of each file, from the matching line
    before/<path>                the file at N-1 on the matching line (absent for an added file)
    after/<path>                 the file at N on the matching line (absent for a deleted file)
    result/<path>                the target file after this revision, once validated
```

`before`, `after` and `result` keep the repository's folder structure, so the same
relative path finds the three states of a file. `result/` is written after step 4: it is
the audit trail of what the target held after each revision, and it is what the
per-revision commits restore ([prepared commits](apply-and-validate.md#prepared-commits)).

## Byte-exact export

Export with the VCS's own export or a byte-exact redirect. A shell that re-encodes its
redirected output (Windows PowerShell 5.1's `>` writes UTF-16) corrupts every file it
writes: run these in a shell whose redirect copies bytes (cmd, bash), or use the export
commands that write files themselves.

## svn

| Need | Command |
|---|---|
| The revision's changed paths | `svn log -v -c 4120 <repo-root-url>` -> `log.txt` |
| Where the target came from (to find the matching line) | `svn log -v --stop-on-copy <target-url>` - its oldest entry shows the copy source; the line that source belongs to is the matching line |
| `before` | `svn export -r 4119 <repo-root-url>/branches/2.x/<path>@4119 before/<path>` |
| `after` | `svn export -r 4120 <repo-root-url>/branches/2.x/<path>@4120 after/<path>` |
| The isolated diff | `svn diff -c 4120 <repo-root-url>/branches/2.x/<path>` -> `diff/<path>.diff` |

The `@<rev>` peg revision names the file as it was then, so a file moved later is still
found. A revision that changed the same file on `trunk` and on `branches/2.x` is taken
from `branches/2.x` when the target descends from it.

## git

| Need | Command |
|---|---|
| The commit's changed paths | `git show --name-status --format=fuller a1b2c3d` -> `log.txt` |
| Lines that contain it | `git branch -a --contains a1b2c3d` |
| The same fix already on another line | `git cherry -v <target-branch> release/2.x` - a `-` marks a commit whose change the target already has |
| `before` | `git show a1b2c3d^:<path>` -> `before/<path>` (byte-exact redirect) |
| `after` | `git show a1b2c3d:<path>` -> `after/<path>` |
| The isolated diff | `git diff a1b2c3d^ a1b2c3d -- <path>` -> `diff/<path>.diff` |
| The order | `git rev-list --reverse release/2.x` filtered to the selected commits |

When the fix exists as different commits on different lines, take the commit on the line
the target descends from. Which line a release is cut from is the team's convention: take
it from the case's notes or the owner, and confirm that the line contains the target's
base (`git merge-base --is-ancestor <target-base> <line>` succeeds). A merge commit is not
a revision to carry: carry the commits it brought, or stop and ask.

`git show <commit>:<path>` writes the bytes stored in the repository; a working copy with
line-ending conversion holds other bytes. Compare working files through the repository's
own filters ([apply-and-validate](apply-and-validate.md#comparing-files)).

## The manifest

A working file outside the knowledge base: no Scope line.

```markdown
# Revision <N> - <first line of its message>

| Field | Value |
|---|---|
| Revision | <N>, <author>, <date> |
| Message | <full message> |
| Matching line | <line> - why: <the target descends from it> |
| Other lines in this revision | <none, or the paths not used> |

## Files
| Path | Target file | source = before? | Kind | Validation | Note |
|---|---|---|---|---|---|
| src/orders/Totals.src | src/orders/Totals.src | yes | advance | after: identical | - |
| src/orders/Lines.src | src/orders/Lines.src | no | isolated diff | hunks: same 2 of 2, nothing else | target diverged in r3990 |

## Excluded (not backported)
| Path | Reason |
|---|---|
| build/OrdersService.proj | project metadata, regenerated by the IDE |

## Deleted or moved (prepared, not run)
| Path | Command for the human |
|---|---|

## Open
- <blockers, questions for the owner>
```

`Kind` is one of new, revert, advance, isolated diff, stop. The "Target file" column maps
each path once when the target working copy's layout differs from the source's (a case
whose hotfix tree holds files in another arrangement); the method does not change.

## The session file

```markdown
# Backport <backport-id>

## Inputs
| Input | Value |
|---|---|
| Revisions, in order | r4120, r4135 |
| Matching line | branches/2.x |
| Target line, base | hotfix/2.1.7-1, base = tags/2.1.7 at r4001 |
| Target working copy | <path> (clean at the start: yes) |
| Exclusions | <patterns and files, with the reason> |
| Owner | <name>; go logged in <WORKLOG path> |

## File registry (files touched by more than one revision)
| File | Revisions | Current state | Note |
|---|---|---|---|
| src/orders/Lines.src | r4120, r4135 | base + r4120 + r4135 | r4135 applied on the target file, not on the base |

## End validation
| File | Last revision | Check | Result |
|---|---|---|---|
Pass: <n> of <n>. Spurious files: none. Excluded files in the change set: none.

## Prepared commands
<per revision, in order - see apply-and-validate.md#prepared-commits>
```
